# omonitor

내 컴퓨터에서 실행 중인 [OpenCode 2](https://opencode.ai/v2/docs/cli/)(`opencode2`) 세션을 브라우저에서 보고 관리하는 로컬 대시보드입니다. opencode2는 사용자마다 백그라운드 서버 하나(`opencode2 service`)를 띄워 모든 세션을 맡기며, omonitor는 그 서버에 붙어 세션을 보드·타임라인·작성창으로 보여 줍니다. 시뮬레이터는 별도 명령으로만 실행합니다.

예전 버전은 [omo](https://github.com/code-yeongyu/oh-my-openagent)(`omo host`)도 지원했지만 지금은 opencode2 전용입니다. omo 세션을 보려면 omo 지원이 남아 있는 마지막 커밋 `dbe5fba`를 쓰세요.

## 시작하기

[Bun](https://bun.sh) 1.4.2 이상과 `opencode2`가 필요합니다. 터미널 라이브러리를 설치하며, 빌드 단계는 없습니다.

```sh
git clone https://github.com/jcwleo/omonitor.git
cd omonitor
bun install      # 브라우저 터미널과 화면 복원 라이브러리를 설치합니다
bun link          # omonitor 명령을 등록합니다 (~/.bun/bin/omonitor)
omonitor start    # 백그라운드 서비스로 실행하고, 로그인할 때마다 자동으로 시작합니다
omonitor open     # 브라우저에서 http://127.0.0.1:4800 을 엽니다
```

`omonitor start`는 사용자 서비스를 등록합니다. macOS에서는 LaunchAgent(`~/Library/LaunchAgents/dev.omonitor.plist`), Linux에서는 systemd 사용자 서비스(`~/.config/systemd/user/omonitor.service`)입니다. 대시보드가 비정상 종료되면 약 10초 뒤 다시 띄웁니다. 서비스는 내려받은 폴더에서 실행되므로 폴더를 옮기거나 지우지 마세요. `omonitor start`를 실행할 때의 `PATH`가 서비스에 저장되므로, 그 셸에서 `opencode2`를 찾을 수 있어야 합니다.

업데이트는 `omonitor update`입니다. 새 커밋을 fast-forward로 받고, `package.json`이나 `bun.lock`이 바뀌었으면 `bun install`을, 서버 코드(`.ts`)가 바뀌었으면 서비스 재시작까지 합니다. 화면 파일만 바뀐 업데이트는 재시작 없이 새로고침만 하면 됩니다. 대시보드는 30분마다 새 버전을 확인해, 있으면 오른쪽 아래 opencode2 버전 위에 **omonitor 업데이트 (커밋 수)** 를 띄웁니다. 누르면 새 커밋 목록을 보여 주고 바로 업데이트합니다. 재시작하면 대시보드에 열린 터미널이 모두 닫히므로, 확인창과 `omonitor update`가 먼저 알려 줍니다. 직접 고친 파일이나 로컬 커밋이 있으면 자동으로 합치지 않으니 `git pull` 후 `omonitor restart` 하세요.

| 명령 | 하는 일 |
| --- | --- |
| `omonitor start` | 서비스를 등록·시작하고 로그인 시 자동 시작을 켭니다. 이미 실행 중이면 설정을 다시 적용합니다 |
| `omonitor stop` | 서비스를 멈추고 자동 시작을 끕니다. opencode2 서버는 그대로 둡니다 |
| `omonitor update` | 새 버전을 받아 적용합니다 (필요하면 `bun install`과 서비스 재시작) |
| `omonitor restart` | 서비스를 다시 시작합니다 |
| `omonitor status` | 서비스, 대시보드 응답, omonitor 새 버전 여부를 보여 줍니다 |
| `omonitor open` / `logs` | 브라우저로 열기 / 서버 로그(`~/.omonitor/server.log`) 따라 보기 |
| `omonitor run` | 서비스 없이 터미널에서 직접 실행합니다 (Ctrl-C로 종료, `--mock`은 시뮬레이터) |

- 백그라운드 서비스는 macOS와 Linux만 지원합니다. Windows에서는 `omonitor run`을 쓰세요. Linux 서비스는 아직 실제 환경에서 시험하지 않았고, 로그인하지 않은 상태에서도 켜 두려면 `loginctl enable-linger`가 필요합니다.
- 4800 포트를 이미 다른 프로세스(직접 띄운 `bun start` 등)가 쓰고 있으면 `omonitor start`는 등록하지 않고 알려 줍니다. `PORT=4810 omonitor start`처럼 다른 포트를 쓸 수 있습니다.
- `bun start`는 저장소에서 서버만 실행하는 개발용 명령입니다.

백엔드(`opencode.ts`)는 opencode 서비스가 `~/.local/state/opencode/service.json`에 적어 둔 주소와 비밀번호로 접속합니다(`opencode2 service status`로 확인). 서버가 응답하지 않으면 `opencode2 service start`로 띄웁니다. 비밀번호는 브라우저로 보내지 않습니다. 연결에 실패하면 상단 배너에 사유와 재시도 상태가 표시됩니다.

| 변수 | 기본값 | 용도 |
| --- | --- | --- |
| `PORT` | `4800` | 대시보드 포트 |
| `OPENCODE_SERVICE_FILE` | `~/.local/state/opencode/service.json` | opencode2 서비스가 주소와 비밀번호를 적어 두는 파일 |
| `OMONITOR_ORIGINS` | (없음) | 추가로 허용할 Origin (쉼표 구분). 터널·리버스 프록시 주소로 열 때 지정합니다. 예: `https://omo.example.com` |

`omonitor start`를 실행할 때의 값이 서비스에 저장되므로, 바꾸려면 새 값으로 `omonitor start`를 다시 실행합니다.

시연용 데이터를 보려면 **별도로** `omonitor run --mock`(또는 `bun run mock`)을 실행합니다. 실제 모드는 연결 실패 시 시뮬레이터로 전환하지 않습니다.

## 세션 사용

- 세션 목록·기록·실시간 진행(텍스트, 추론, 도구 호출)·컨텍스트 사용량은 서버 API와 이벤트 스트림(`/api/event`)에서 읽습니다. 세션은 모두 서버가 들고 있어서, 세션을 열면 바로 구독합니다. 작업 중이거나 답을 기다리는 세션은 열지 않아도 따라갑니다.
- 메시지 보내기, 작업 중 끼어들기, 중단, 모델·effort(variant) 변경, 이름 변경, 압축, 복제, 보관(opencode 자체 보관), 삭제를 지원합니다. `/명령`은 opencode 명령으로, `/skill:이름`은 스킬을 붙인 프롬프트로 보냅니다.
- 대화창에서 내 메시지를 누르면(키보드는 Enter나 Space) TUI처럼 **되돌리기·복사·여기서 분기**가 나옵니다.
  - **되돌리기**는 그 메시지부터 뒤의 대화와 그동안 바뀐 파일을 되돌리고, 그 메시지를 입력창에 다시 넣습니다. 대화 끝의 카드에 되돌린 메시지 수와 복원한 파일이 보이고 "되살리기"로 둘 다 되돌려 놓을 수 있습니다. 다음 메시지를 보내면 opencode가 되돌린 내용을 확정해 지웁니다. 작업 중에는 쓸 수 없습니다.
  - **여기서 분기**는 그 메시지 직전까지를 복사한 새 세션을 열고 그 메시지를 입력창에 넣습니다. 세션 메뉴의 "복제 (fork)"는 지금까지 전체를 복사합니다.
  - 세션 메뉴(또는 ⌘K)의 **발화로 이동…**은 이 세션의 내 메시지를 최근 것부터 보여 주고, 고르면 대화창이 그 메시지로 스크롤합니다. 대화창에 불러온 최근 60턴 안에서만 찾습니다.
- 권한 요청은 승인 카드로, 질문 도구와 폼은 질문 카드로 표시합니다. "세션 동안 허용"은 opencode의 `always` 응답이라 opencode가 그 규칙을 저장합니다.
- 하위 에이전트(subagent)는 부모 세션의 에이전트 탭에 보이고, 보드에는 최상위 세션만 나옵니다. 하위 에이전트가 권한 승인이나 질문·폼 답을 기다리면 최상위 세션의 대화창과 보드 카드에 "서브에이전트 승인"·"서브에이전트 질문" 카드로 띄웁니다. 거기서 누른 답은 그 하위 에이전트에게 갑니다.
- 턴이 끝나 대기나 오류가 된 세션을 아직 열어 보지 않았으면 보드 카드에 강조색 점과 테두리를, 세션 목록에 점과 굵은 이름을 표시합니다. 세션을 열면 사라집니다. 이 읽지 않음 표시는 대시보드 서버(`~/.omonitor/unread.json`)가 기기 공통으로 관리하므로, 한 기기에서 세션을 열면 열려 있는 다른 대시보드에서도 바로 사라집니다. 세션을 보관하거나 삭제해도 사라집니다. 시뮬레이터(`--mock`)는 브라우저(localStorage)에 따로 셉니다.
- 세션 작성창의 모델 메뉴에서 ☆를 누른 모델은 즐겨찾기가 됩니다. 즐겨찾기가 하나라도 있으면 모델 메뉴와 새 세션 창은 즐겨찾기와 지금 고른 모델만 보여 주고, "모든 모델 보기"로 나머지를 펼칩니다. 즐겨찾기는 브라우저(localStorage)에 저장합니다.
- **opencode2 업데이트**: 오른쪽 아래 배지에 설치된 opencode2 버전이 보입니다. npm의 `@opencode/cli`에 새 버전이 있으면 "업데이트"로 바뀌고, 누르면 확인 창을 거쳐 `opencode upgrade` 뒤 `opencode service restart`로 공유 서버를 새 버전으로 다시 시작합니다. 터미널에서 업그레이드해 서버가 아직 이전 버전으로 돌고 있으면 "opencode 서버 재시작 필요"로 표시합니다. 서버가 다시 시작하는 동안 작업 중인 세션의 실행이 끊길 수 있고, 대시보드는 자동으로 다시 연결합니다.
- **요금제 사용량**: 헤더(휴대전화는 상단 바 아래)에 Claude·ChatGPT 구독의 5시간·주간 사용률을 표시합니다. 칩에 마우스를 올리면 모든 한도와 초기화까지 남은 시간이 나옵니다. 백엔드가 아래 **구독 계정**에서 omonitor가 직접 로그인한 계정으로 Claude Code `/usage`, Codex `/status`와 같은 비공개 엔드포인트를 읽으며, 로그인하지 않은 공급자는 "로그인 확인"으로 표시합니다. 토큰은 브라우저로 보내지 않습니다. 화면이 보이는 동안 1분마다, 턴이 끝날 때, 로그인·로그아웃 직후에 다시 읽습니다(백엔드 캐시: Claude 3분, ChatGPT 30초. Claude 사용량 API는 30초 간격 호출에도 429를 돌려줍니다).
- **구독 계정**: 설정(헤더의 설정 버튼, 휴대전화는 왼쪽 서랍의 "설정")의 "구독 계정"에서 사용량을 읽을 Claude·ChatGPT 계정에 로그인합니다. 공급자마다 계정 하나입니다.
  - opencode·Claude Code·Codex 같은 CLI의 로그인과 따로 `~/.omonitor/usage-auth/accounts.sqlite`에 저장합니다(폴더 권한 700, 파일 권한 600). 이미 로그인된 CLI 인증을 자동으로 가져오지 않으므로, 처음 한 번은 여기서 로그인해야 사용량이 나옵니다. 개발·검증 서버는 `OMONITOR_USAGE_DIR`로 별도 저장 폴더를 지정할 수 있습니다.
  - "로그인"을 누르면 나오는 "로그인 페이지 열기"로 브라우저에서 승인합니다. Claude는 승인 후 표시되는 코드(`코드#state`)를 붙여넣습니다. ChatGPT는 omonitor를 실행 중인 Mac의 브라우저에서 로그인하면 `http://localhost:1455/auth/callback`으로 돌아오면서 자동으로 연결됩니다. 로그인 요청은 10분 뒤 만료됩니다.
  - 공급자가 미리 정해 둔 콜백 주소로만 돌아오므로 대시보드 주소나 터널 주소로는 받을 수 없습니다. 휴대전화처럼 다른 기기에서 로그인했거나 1455 포트를 다른 프로그램이 쓰고 있으면, 로그인 후 열리지 않는 페이지의 주소창 주소 전체를 "이동한 주소"에 붙여넣으세요.
  - 승인 화면에 보이는 권한은 사용량 조회보다 넓을 수 있습니다(CLI와 같은 로그인 방식을 씁니다). omonitor는 그 권한으로 사용량 엔드포인트만 호출합니다.
  - 토큰 갱신은 자동입니다. 로그아웃은 omonitor에 저장된 로그인만 지우며, 공급자 쪽 세션이나 다른 프로그램의 로그인은 그대로입니다. 계정을 바꾸려면 로그아웃한 뒤 다시 로그인하세요.
- 대시보드 서버를 다시 시작해도 열린 탭이 새 세션 키를 받아 자동으로 다시 연결합니다.
- 세션 작성창이나 새 세션 창에 이미지를 붙여넣거나(⌘V) 끌어다 놓거나 "이미지" 버튼으로 고르면(png·jpeg·gif·webp, 20MB 이하) `~/.omonitor/uploads/`에 저장하고, 메시지에 파일 경로를 붙여 보냅니다. 클립보드에 텍스트가 함께 있으면 텍스트만 붙여넣습니다. 에이전트가 `read` 도구로 그 파일을 열어 봅니다. 저장된 파일은 자동으로 지우지 않습니다.
- 에이전트가 도구로 본 이미지(`read`로 연 이미지 파일, 스크린샷 등)는 타임라인의 그 도구 줄 아래에 썸네일로 표시하고, 누르면 원본을 엽니다. 이미지는 opencode 서버에서 읽어 `/tool-images/…`로 제공합니다(png·jpeg·gif·webp).
- **푸시 알림**: 설정(헤더의 설정 버튼, 휴대전화는 왼쪽 서랍)에서 "푸시 알림"을 켜면 그 기기로 알림이 옵니다. 알림을 누르면 해당 세션이 열립니다.
  - 서브에이전트를 기다리는 동안에는 완료 알림이 오지 않습니다. 메인 세션이 결과를 반영해 답변을 마치면 한 번만 알립니다. 오류로 멈추면 별도로 알리고, 사용자가 중단한 턴은 알리지 않습니다. 앱을 닫아 둬도 받습니다.
  - 질문과 승인은 대시보드 서버가 직접 보내고, 그 세션을 구독한 대시보드도 넘깁니다(같은 요청은 한 번만 갑니다). 하위 에이전트의 요청은 제목에 "서브에이전트"가 붙습니다.
  - 앱 아이콘에 읽지 않은 세션 수를 뱃지로 표시합니다(같은 세션의 알림은 하나로 셉니다). 다른 기기에서 읽으면, 열려 있는 앱은 바로 줄고 닫혀 있는 앱은 다음 알림을 받거나 앱을 열 때 맞춰집니다. 알림을 받을 때 대시보드 서버의 현재 숫자를 다시 읽으므로, 그사이 다른 기기에서 읽은 세션은 빠집니다(서버에 닿지 않으면 알림에 담긴 숫자를 씁니다). 푸시 알림을 끄면 숫자도 지웁니다. 뱃지를 지원하지 않는 브라우저에서는 숫자 없이 알림만 옵니다.
  - iPhone·iPad는 홈 화면에 추가한 앱(iOS 16.4 이상)에서만 켤 수 있고, 대시보드를 HTTPS(예: Cloudflare 터널)로 열어야 합니다. Mac은 Chrome이 실행 중일 때 받습니다.
  - 푸시 키와 등록된 기기는 `~/.omonitor/push.json`에 있습니다. 이 파일을 지우면 모든 기기에서 다시 켜야 합니다.
- opencode2는 아직 베타이고 API도 실험 단계입니다. opencode 2.1.4에서 확인했고, 메시지 동작(되돌리기·복사·분기·발화로 이동)은 2.3.2에서 확인했습니다.

## 구조와 보안

### 세션 터미널

세션의 **Todo · 에이전트 · 변경 · Git · 터미널** 탭에서 **터미널 시작**을 누르면 해당 세션의 작업 폴더에 셸이 열립니다. leominal의 xterm 화면과 한국어 textarea 입력 방식을 사용하며, 모바일에서는 Ctrl·Esc·Tab·방향키·Enter 보조키와 붙여넣기를 제공합니다.

탭을 바꾸거나 페이지를 새로고침해도 서버가 실행 중이면 같은 셸과 화면에 다시 연결합니다. **종료**는 셸과 그 안에서 실행 중인 작업을 끝내며, 대시보드 서버를 재시작해도 터미널은 종료됩니다. 휴대전화에서는 터미널 탭을 보는 동안 메시지 작성창을 숨겨 터미널 입력 공간을 확보합니다.

상단의 **터미널** 탭(⌥3, 휴대전화는 하단 탭)에서 열려 있는 셸을 모두 볼 수 있습니다. 셸마다 세션, 작업 폴더, 안에서 실행 중인 프로그램, 메모리(셸과 하위 프로세스 합계), 마지막 활동 시각을 보여 주고, 세션으로 이동하거나 종료할 수 있습니다. 실행 중인 프로그램이 없고 아무도 보고 있지 않은 셸은 하루 동안 입출력이 없으면 자동으로 닫히고, 끝난 셸의 화면 기록은 10분 뒤 정리됩니다. 프로그램이 실행 중인 셸은 자동으로 닫지 않습니다. 세션을 삭제하면 그 세션의 셸도 종료되고, 보관하면 프로그램이 없는 셸만 닫습니다. 세션 목록의 터미널 아이콘은 셸이 열려 있는 세션을 나타내며, 프로그램이 실행 중이면 강조색으로 표시합니다.

이 터미널은 대시보드가 실행 중인 컴퓨터의 실제 셸입니다. 시연 모드에서도 터미널은 실제로 실행되며, 존재하지 않는 시연 작업 폴더에서는 시작할 수 없습니다. 터미널 기능은 macOS와 Linux에서 지원합니다.

### Git 그래프

세션의 **Git** 탭은 작업 폴더 저장소의 현재 브랜치, 추적하는 원격 브랜치와의 차이(↑ 올리지 않은 커밋, ↓ 받지 않은 커밋), 커밋하지 않은 변경 파일 수를 보여 주고, 그 아래에 모든 로컬·원격 브랜치와 태그의 최근 커밋 200개를 `git log --graph`처럼 선으로 이어 그립니다. 커밋을 누르면 전체 해시, 작성자, 시각, 병합 여부가 보입니다. 탭을 보는 동안 10초마다 새로 읽습니다.

읽기 전용입니다. `git status`가 인덱스 잠금을 잡지 않도록 `GIT_OPTIONAL_LOCKS=0`으로 실행하므로 에이전트의 git 작업과 부딪히지 않고, 저장소 설정의 `core.fsmonitor` 명령도 실행하지 않습니다.

### 브랜치와 워크트리

보드 카드, 세션 목록, 세션 헤더에 세션 작업 폴더의 브랜치가 보입니다. 폴더 아이콘은 워크트리, 가지 아이콘은 기본 체크아웃의 브랜치입니다. 옆에는 올리지 않은 커밋(↑), 받지 않은 커밋(↓), 커밋하지 않은 변경 수가 붙습니다. 작업 폴더의 워크트리가 이미 지워졌으면 "정리됨"을 붙입니다.

프로젝트는 폴더 이름이 아니라 저장소로 묶으므로, 워크트리 폴더에서 시작한 세션도 원래 프로젝트에 붙습니다. 묶음 머리에는 기본 체크아웃의 브랜치와 다른 워크트리 수가 보입니다. 세션 목록에서 워크트리 수를 누르면 워크트리마다 브랜치, 동기화 상태, 거기서 일하는 세션 수가 펼쳐집니다. Git 탭은 세션의 워크트리를 그리고, 워크트리가 둘 이상이면 그 목록을 위에 보여 줍니다. 다른 워크트리에서 체크아웃된 브랜치는 그래프에서 테두리로 표시합니다. 대시보드는 화면을 보는 동안 20초마다, 그리고 턴이 끝나면 새로 읽습니다.

### 연결 경계

브라우저는 `127.0.0.1:4800/ws`에 연결합니다. Bun 백엔드(`opencode.ts`)가 opencode 서버의 HTTP API와 이벤트 스트림에 붙어 있고, 브라우저와는 대시보드 프로토콜(app-server 호환 JSON-RPC)로 주고받으며 양쪽을 번역합니다. 브라우저는 opencode 서버에 직접 닿지 않습니다. 대시보드는 정적 런타임 파일만 서빙하며 `/ws`, `/api/*`에 로컬 Origin과 실행별 세션 키를 요구합니다. 붙여넣은 이미지(`/uploads/<무작위 UUID>`)는 `<img>`로 불러오도록 키 없이 서빙하며, 추측할 수 없는 이름으로만 열립니다.

터미널의 `/api/terminal`, `/api/terminals`와 `/terminal-ws`도 실행별 세션 키와 허용된 Origin으로 보호합니다. `/terminal-ws`는 Origin 없는 연결도 거절합니다. 터널을 통해 접속할 때에는 기존 `OMONITOR_ORIGINS`에 해당 주소를 지정하세요. xterm 라이브러리는 서버에서 직접 제공합니다.

이 앱은 **로컬 전용**으로 `127.0.0.1`에 바인딩됩니다. 인터넷이나 공용 Wi-Fi에 직접 노출하지 마세요. 에이전트는 셸 실행과 파일 수정을 수행할 수 있으므로, 이 대시보드에 접근할 수 있는 사람은 로컬 사용자 권한으로 작업할 수 있습니다.

화면 런타임(`support.js`)의 React와 Google Fonts는 외부 CDN에서 내려받습니다. 완전한 오프라인 앱은 아닙니다.
