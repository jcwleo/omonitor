# omonitor

내 컴퓨터에서 실행 중인 [omo](https://github.com/code-yeongyu/oh-my-openagent) 세션을 브라우저에서 보고 관리하는 로컬 대시보드입니다. 기본 실행은 **실제 omo host**(여러 세션을 한 프로세스에서 돌리는 omo의 공유 RPC 데몬)에 연결합니다. 시뮬레이터는 별도 명령으로만 실행합니다.

omo 5.1.34(senpi 2026.10.15)부터 `omo app-server`가 없어졌습니다. omonitor는 이제 `omo host`에 붙으므로 omo 5.1.34 이상이 필요합니다. 예전에 app-server를 로그인 때 띄우도록 LaunchAgent(예: `dev.omo.app-server`)를 만들었다면, 새 omo에서는 실패를 반복하므로 `launchctl bootout gui/$(id -u)/dev.omo.app-server`로 내리고 plist를 지우세요.

## 시작하기

[Bun](https://bun.sh) 1.4.2 이상과 `omo`가 필요합니다. 터미널 라이브러리를 설치하며, 빌드 단계는 없습니다.

```sh
git clone https://github.com/jcwleo/omonitor.git
cd omonitor
bun install      # 브라우저 터미널과 화면 복원 라이브러리를 설치합니다
bun link          # omonitor 명령을 등록합니다 (~/.bun/bin/omonitor)
omonitor start    # 백그라운드 서비스로 실행하고, 로그인할 때마다 자동으로 시작합니다
omonitor open     # 브라우저에서 http://127.0.0.1:4800 을 엽니다
```

`omonitor start`는 사용자 서비스를 등록합니다. macOS에서는 LaunchAgent(`~/Library/LaunchAgents/dev.omonitor.plist`), Linux에서는 systemd 사용자 서비스(`~/.config/systemd/user/omonitor.service`)입니다. 서비스는 시작할 때 omo host가 꺼져 있으면 `omo host ensure`로 함께 켜고(대시보드도 연결할 host가 없으면 같은 명령으로 띄웁니다), 대시보드가 비정상 종료되면 약 10초 뒤 다시 띄웁니다. 서비스는 내려받은 폴더에서 실행되므로 폴더를 옮기거나 지우지 마세요.

업데이트는 `omonitor update`입니다. 새 커밋을 fast-forward로 받고, `package.json`이나 `bun.lock`이 바뀌었으면 `bun install`을, 서버 코드(`.ts`)가 바뀌었으면 서비스 재시작까지 합니다. 화면 파일만 바뀐 업데이트는 재시작 없이 새로고침만 하면 됩니다. 대시보드는 30분마다 새 버전을 확인해, 있으면 오른쪽 아래 omo 버전 위에 **omonitor 업데이트 (커밋 수)** 를 띄웁니다. 누르면 새 커밋 목록을 보여 주고 바로 업데이트합니다. 재시작하면 대시보드에 열린 터미널이 모두 닫히므로, 확인창과 `omonitor update`가 먼저 알려 줍니다. 직접 고친 파일이나 로컬 커밋이 있으면 자동으로 합치지 않으니 `git pull` 후 `omonitor restart` 하세요.

| 명령 | 하는 일 |
| --- | --- |
| `omonitor start` | 서비스를 등록·시작하고 로그인 시 자동 시작을 켭니다. 이미 실행 중이면 설정을 다시 적용합니다 |
| `omonitor stop` | 서비스를 멈추고 자동 시작을 끕니다. omo host는 그대로 두며, 붙은 클라이언트와 작업이 없으면 15분 뒤 스스로 종료합니다 |
| `omonitor update` | 새 버전을 받아 적용합니다 (필요하면 `bun install`과 서비스 재시작) |
| `omonitor restart` | 서비스를 다시 시작합니다 |
| `omonitor status` | 서비스, 대시보드 응답, omo host 상태(엔진 버전·열린 세션 수), omonitor 새 버전 여부를 보여 줍니다 |
| `omonitor open` / `logs` | 브라우저로 열기 / 서버 로그(`~/.omonitor/server.log`) 따라 보기 |
| `omonitor run` | 서비스 없이 터미널에서 직접 실행합니다 (Ctrl-C로 종료, `--mock`은 시뮬레이터) |

- 백그라운드 서비스는 macOS와 Linux만 지원합니다. Windows에서는 `omonitor run`을 쓰세요. Linux 서비스는 아직 실제 환경에서 시험하지 않았고, 로그인하지 않은 상태에서도 켜 두려면 `loginctl enable-linger`가 필요합니다.
- 4800 포트를 이미 다른 프로세스(직접 띄운 `bun start` 등)가 쓰고 있으면 `omonitor start`는 등록하지 않고 알려 줍니다. `PORT=4810 omonitor start`처럼 다른 포트를 쓸 수 있습니다.
- `bun start`는 저장소에서 서버만 실행하는 개발용 명령입니다. omo host는 대시보드가 연결할 때 필요하면 띄웁니다.

연결에 실패하면 상단 배너에 사유와 재시도 상태가 표시됩니다. `omonitor status`나 `omo host status`로 host를 확인하세요. 기본 소켓은 omo와 같은 `~/.omo/agent/rpc/rpc.sock`이며, 같은 사용자만 접근할 수 있는 로컬 소켓이라 별도 토큰이 없습니다.

| 변수 | 기본값 | 용도 |
| --- | --- | --- |
| `PORT` | `4800` | 대시보드 포트 |
| `OMO_HOST_SOCKET` | `~/.omo/agent/rpc/rpc.sock` | 붙을 omo host 소켓 (`omo host --socket`과 같은 값) |
| `OMONITOR_ORIGINS` | (없음) | 추가로 허용할 Origin (쉼표 구분). 터널·리버스 프록시 주소로 열 때 지정합니다. 예: `https://omo.example.com` |

예: 따로 띄운 host에 붙이려면 `OMO_HOST_SOCKET=/tmp/my-host.sock omonitor start`를 사용합니다. `omonitor start`를 실행할 때의 값(과 `PATH`)이 서비스에 저장되므로, 바꾸려면 새 값으로 `omonitor start`를 다시 실행합니다.

시연용 데이터를 보려면 **별도로** `omonitor run --mock`(또는 `bun run mock`)을 실행합니다. 실제 모드는 연결 실패 시 시뮬레이터로 전환하지 않습니다.

## 실제 세션 사용

- 세션 목록과 기록은 백엔드가 세션 파일(`~/.omo/agent/sessions/…jsonl`)을 **직접 읽어** 보여 줍니다. 보드를 열거나 세션을 보는 것만으로는 어떤 세션도 omo host에 로드되지 않습니다.
- omo host에 열려 있는 세션(다른 클라이언트가 연 것 포함)은 자동으로 구독합니다. host는 모든 연결에 턴 시작·종료를 알리므로, 구독하지 않은 세션도 작업 중·대기 상태는 보입니다. 질문은 보드의 "입력 필요" 열과 세션 화면에 표시합니다.
- 턴이 끝나 대기나 오류가 된 세션을 아직 열어 보지 않았으면 보드 카드에 강조색 점과 테두리를, 세션 목록에 점과 굵은 이름을 표시합니다. 세션을 열면 사라집니다. 마지막으로 본 시각은 브라우저(localStorage)에 저장하므로 기기마다 따로 셉니다. 이 기능을 처음 켰을 때 이미 끝나 있던 세션과 터미널에서 돌리는 세션은 표시하지 않습니다.
- 로드되지 않은 세션에 메시지를 보내거나 구독하면 확인 창을 거친 뒤 omo host에 엽니다(`open_session`). 대시보드가 연 세션은 대시보드를 닫거나 다시 시작해도 host에서 계속 돌고, 30분 동안 활동이 없으면 host가 내려 둡니다.
- 터미널 omo가 열고 있는 세션은 목록에 "터미널에서 실행 중일 수 있음"으로 표시되고, omo host가 열기를 거절합니다. 터미널에서 세션을 끝낸 뒤 이어 받으세요.
- **목표(goal)나 끝나지 않은 todo가 있는 세션은 omo host에 로드되는 순간 omo가 자동으로 이어서 작업할 수 있습니다.** 대시보드가 구독 중이면 진행 상황과 질문이 화면에 보이지만, 원치 않으면 로드하기 전에 터미널에서 `/stop-continuation`으로 멈추세요.
- 기록은 세션 파일에서 읽으므로 omo host가 바뀌어도 대화·도구 호출·todo가 그대로 보입니다. 추론 내용과 도구의 실시간 출력은 대시보드가 지켜본 턴에만 표시됩니다.
- 질문(`ask_user_question`)과 확장이 띄우는 선택·확인·입력 창(권한 승인 포함)은 모두 질문 카드로 표시합니다. omo의 기본 권한 설정(`full-access`)은 승인을 묻지 않습니다. `eval` 안에서 실행하는 셸 명령은 omo 권한 검사 대상도 아닙니다.
- 모델을 바꾸면 터미널의 `/model`처럼 omo의 기본 모델도 그 모델로 바뀝니다(omo host의 `set_model` 동작). 추론 단계(effort)는 그 세션에만 적용합니다. 새 세션 창에서 고른 모델과 effort는 기본 모델을 바꾸지 않습니다.
- 세션 작성창의 모델 메뉴에서 ☆를 누른 모델은 즐겨찾기가 됩니다. 즐겨찾기가 하나라도 있으면 모델 메뉴와 새 세션 창은 즐겨찾기와 지금 고른 모델만 보여 주고, "모든 모델 보기"로 나머지를 펼칩니다. 즐겨찾기는 브라우저(localStorage)에 저장합니다.
- 목표는 omo의 `/goal` 명령으로 바꿉니다(설정·일시정지·재개·해제). 완료 표시는 에이전트가 직접 하므로 대시보드에서는 할 수 없습니다.
- omo host에는 보관 기능이 없어서, 보관한 세션 목록은 omonitor가 `~/.omonitor/archived.json`에 따로 둡니다. 세션을 삭제하면 세션 파일과 옆의 부속 파일·목표를 `~/.omonitor/trash/`로 옮깁니다. 작업 중이거나 터미널·다른 클라이언트가 열고 있는 세션은 삭제하지 않습니다.
- 에이전트 탭과 컨텍스트 사용량은 세션 파일에서 계산합니다(`task` 실행·완료 기록, 마지막 응답의 토큰 사용량 ÷ 모델 컨텍스트 창). 턴과 서브에이전트 호출이 끝날 때마다 갱신합니다.
- **omo 업데이트**: 오른쪽 아래 omo 버전 버튼으로 `omo update`를 실행하면 이어서 `omo host ensure`가 실행 중인 host를 새 엔진으로 넘깁니다. 작업 중인 세션은 끊기지 않고 하던 턴을 마친 뒤 새 host로 옮겨지며, 대시보드는 자동으로 다시 연결합니다.
- **요금제 사용량**: 헤더(휴대전화는 상단 바 아래)에 omo가 로그인한 Claude·ChatGPT 구독의 5시간·주간 사용률을 표시합니다. 칩에 마우스를 올리면 모든 한도와 초기화까지 남은 시간이 나옵니다. 백엔드가 `~/.omo/agent/auth.json`의 토큰으로 Claude Code `/usage`, Codex `/status`와 같은 비공개 엔드포인트를 읽습니다. 토큰은 브라우저로 보내지 않고 직접 갱신하지도 않습니다. 만료된 토큰은 omo가 다음 요청 때 갱신할 때까지 "갱신 대기"로 표시합니다. 화면이 보이는 동안 1분마다, 그리고 턴이 끝날 때 다시 읽습니다(백엔드 캐시: Claude 3분, ChatGPT 30초. Claude 사용량 API는 30초 간격 호출에도 429를 돌려줍니다).
- 대시보드 서버를 다시 시작해도 열린 탭이 새 세션 키를 받아 자동으로 다시 연결합니다.
- 세션 작성창이나 새 세션 창에 이미지를 붙여넣거나(⌘V) 끌어다 놓거나 "이미지" 버튼으로 고르면(png·jpeg·gif·webp, 20MB 이하) `~/.omonitor/uploads/`에 저장하고, 메시지에 파일 경로를 붙여 보냅니다. 클립보드에 텍스트가 함께 있으면 텍스트만 붙여넣습니다. 에이전트가 `read` 도구로 그 파일을 열어 봅니다. 이미지를 지원하지 않는 모델에서는 이미지가 빠집니다. 저장된 파일은 자동으로 지우지 않습니다.
- 에이전트가 도구로 본 이미지(`read`로 연 이미지 파일, `eval`의 화면 출력과 스크린샷 등)는 타임라인의 그 도구 줄 아래에 썸네일로 표시하고, 누르면 원본을 엽니다. 이미지는 세션 파일에서 바로 읽어 `/tool-images/…`로 제공합니다(png·jpeg·gif·webp).
- **푸시 알림**: 설정(헤더의 설정 버튼, 휴대전화는 왼쪽 서랍)에서 "푸시 알림"을 켜면 그 기기로 알림이 옵니다. 알림을 누르면 해당 세션이 열립니다.
  - 턴이 끝나 대기로 바뀌거나 오류로 멈추면 대시보드 서버가 직접 알아채고 보냅니다. 앱을 닫아 둬도 받습니다. 사용자가 중단한 턴은 알리지 않습니다.
  - 턴이 끝나도 그 요청 이후 시작한 백그라운드 작업(분리된 eval 셀, 모니터, 백그라운드 서브에이전트)이 남아 있으면 완료 알림을 보내지 않습니다. 그 작업이 끝나면 세션이 다시 깨어나므로, 남은 작업 없이 끝난 턴에서 한 번만 알립니다. 백그라운드 셸은 서버처럼 끝나지 않는 경우가 많아 세지 않습니다.
  - 질문은 대시보드 서버가 열어 둔 세션에서 오면 서버가 직접 보내고, 그 세션을 구독한 대시보드도 넘깁니다(같은 요청은 한 번만 갑니다).
  - iPhone·iPad는 홈 화면에 추가한 앱(iOS 16.4 이상)에서만 켤 수 있고, 대시보드를 HTTPS(예: Cloudflare 터널)로 열어야 합니다. Mac은 Chrome이 실행 중일 때 받습니다.
  - 푸시 키와 등록된 기기는 `~/.omonitor/push.json`에 있습니다. 이 파일을 지우면 모든 기기에서 다시 켜야 합니다.

## 구조와 보안

### 세션 터미널

세션의 **Todo · 에이전트 · 목표 · 변경 · Git · 터미널** 탭에서 **터미널 시작**을 누르면 해당 세션의 작업 폴더에 셸이 열립니다. leominal의 xterm 화면과 한국어 textarea 입력 방식을 사용하며, 모바일에서는 Ctrl·Esc·Tab·방향키·Enter 보조키와 붙여넣기를 제공합니다.

탭을 바꾸거나 페이지를 새로고침해도 서버가 실행 중이면 같은 셸과 화면에 다시 연결합니다. **종료**는 셸과 그 안에서 실행 중인 작업을 끝내며, 대시보드 서버를 재시작해도 터미널은 종료됩니다. 터미널을 여는 것만으로 omo 세션을 불러오거나 자동으로 이어서 실행하지 않습니다. 휴대전화에서는 터미널 탭을 보는 동안 메시지 작성창을 숨겨 터미널 입력 공간을 확보합니다.

상단의 **터미널** 탭(⌥3, 휴대전화는 하단 탭)에서 열려 있는 셸을 모두 볼 수 있습니다. 셸마다 세션, 작업 폴더, 안에서 실행 중인 프로그램, 메모리(셸과 하위 프로세스 합계), 마지막 활동 시각을 보여 주고, 세션으로 이동하거나 종료할 수 있습니다. 실행 중인 프로그램이 없고 아무도 보고 있지 않은 셸은 하루 동안 입출력이 없으면 자동으로 닫히고, 끝난 셸의 화면 기록은 10분 뒤 정리됩니다. 프로그램이 실행 중인 셸은 자동으로 닫지 않습니다. 세션을 삭제하면 그 세션의 셸도 종료되고, 보관하면 프로그램이 없는 셸만 닫습니다. 세션 목록의 터미널 아이콘은 셸이 열려 있는 세션을 나타내며, 프로그램이 실행 중이면 강조색으로 표시합니다.

이 터미널은 대시보드가 실행 중인 컴퓨터의 실제 셸입니다. 시연 모드에서도 터미널은 실제로 실행되며, 존재하지 않는 시연 작업 폴더에서는 시작할 수 없습니다. 터미널 기능은 macOS와 Linux에서 지원합니다.

### Git 그래프

세션의 **Git** 탭은 작업 폴더 저장소의 현재 브랜치, 추적하는 원격 브랜치와의 차이(↑ 올리지 않은 커밋, ↓ 받지 않은 커밋), 커밋하지 않은 변경 파일 수를 보여 주고, 그 아래에 모든 로콜·원격 브랜치와 태그의 최근 커밋 200개를 `git log --graph`처럼 선으로 이어 그립니다. 커밋을 누르면 전체 해시, 작성자, 시각, 병합 여부가 보입니다. 탭을 보는 동안 10초마다 새로 읽습니다.

읽기 전용입니다. `git status`가 인덱스 잠금을 잡지 않도록 `GIT_OPTIONAL_LOCKS=0`으로 실행하므로 에이전트의 git 작업과 부딪히지 않고, 저장소 설정의 `core.fsmonitor` 명령도 실행하지 않습니다.

### 브랜치와 워크트리

보드 카드, 세션 목록, 세션 헤더에 세션이 일하는 브랜치가 보입니다. 폴더 아이콘은 워크트리, 가지 아이콘은 기본 체크아웃의 브랜치입니다. 옆에는 올리지 않은 커밋(↑), 받지 않은 커밋(↓), 커밋하지 않은 변경 수가 붙습니다. 세션의 작업 폴더는 시작한 곳에 머물지만 에이전트는 `<저장소>/.worktree/<작업>` 같은 다른 워크트리에서 일하기도 합니다. 그래서 세션 파일의 도구 호출이 마지막으로 다룬 그 저장소의 워크트리를 세션의 워크트리로 봅니다. 세션이 `git worktree add`로 만든 워크트리가 이미 지워졌으면 그 브랜치 이름에 "정리됨"을 붙이고, 지운 뒤 기본 체크아웃에서 이어서 일하면 기본 체크아웃의 브랜치로 돌아옵니다. 세션을 omo host에 불러오지 않고 세션 파일만 읽습니다.

프로젝트는 폴더 이름이 아니라 저장소로 묶으므로, 워크트리 폴더에서 시작한 세션도 원래 프로젝트에 붙습니다. 묶음 머리에는 기본 체크아웃의 브랜치와 다른 워크트리 수가 보입니다. 세션 목록에서 워크트리 수를 누르면 워크트리마다 브랜치, 동기화 상태, 거기서 일하는 세션 수가 펼쳐집니다. Git 탭은 세션이 일하는 워크트리를 그리고, 워크트리가 둘 이상이면 그 목록을 위에 보여 줍니다. 다른 워크트리에서 체크아웃된 브랜치는 그래프에서 테두리로 표시합니다. 대시보드는 화면을 보는 동안 20초마다, 그리고 턴이 끝나면 새로 읽습니다.

### 연결 경계

브라우저는 `127.0.0.1:4800/ws`에 연결합니다. Bun 백엔드(`host.ts`)가 omo host 소켓에 연결을 하나 열어 두고, 브라우저와는 예전 app-server와 같은 JSON-RPC로 주고받으며 양쪽을 번역합니다. 브라우저는 host 소켓에 직접 닿지 않습니다. 대시보드는 정적 런타임 파일만 서빙하며 `/ws`, `/api/*`에 로컬 Origin과 실행별 세션 키를 요구합니다. 붙여넣은 이미지(`/uploads/<무작위 UUID>`)는 `<img>`로 불러오도록 키 없이 서빙하며, 추측할 수 없는 이름으로만 열립니다.

터미널의 `/api/terminal`, `/api/terminals`와 `/terminal-ws`도 실행별 세션 키와 허용된 Origin으로 보호합니다. `/terminal-ws`는 Origin 없는 연결도 거절합니다. 터널을 통해 접속할 때에는 기존 `OMONITOR_ORIGINS`에 해당 주소를 지정하세요. xterm 라이브러리는 서버에서 직접 제공합니다.

이 앱은 **로컬 전용**으로 `127.0.0.1`에 바인딩됩니다. 인터넷이나 공용 Wi-Fi에 직접 노출하지 마세요. omo는 셸 실행과 파일 수정을 수행할 수 있으므로, 이 대시보드에 접근할 수 있는 사람은 로컬 사용자 권한으로 작업할 수 있습니다.

화면 런타임(`support.js`)의 React와 Google Fonts는 외부 CDN에서 내려받습니다. 완전한 오프라인 앱은 아닙니다.
